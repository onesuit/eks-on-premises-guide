# 보안

> "Kubernetes 보안은 어디서부터 시작해야 하나요?"

Kubernetes 보안은 복잡해 보이지만, 계층별로 접근하면 체계적으로 관리할 수 있습니다. 이 장에서는 온프레미스 EKS 환경의 보안을 5개 계층으로 나누어 살펴봅니다.

## 보안 5계층 모델

```
┌─────────────────────────────────────────────────────────────────┐
│                    Kubernetes 보안 5계층                        │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │  Layer 5: 데이터 보안                                    │  │
│   │  (Secrets, 암호화, 백업)                                │  │
│   └─────────────────────────────────────────────────────────┘  │
│                              ▲                                  │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │  Layer 4: 워크로드 보안                                  │  │
│   │  (Pod Security, OPA, 런타임 보안)                       │  │
│   └─────────────────────────────────────────────────────────┘  │
│                              ▲                                  │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │  Layer 3: 네트워크 보안                                  │  │
│   │  (Network Policy, Service Mesh, mTLS)                   │  │
│   └─────────────────────────────────────────────────────────┘  │
│                              ▲                                  │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │  Layer 2: 신원 및 접근 관리                              │  │
│   │  (RBAC, IAM, ServiceAccount)                            │  │
│   └─────────────────────────────────────────────────────────┘  │
│                              ▲                                  │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │  Layer 1: 인프라 보안                                    │  │
│   │  (노드 하드닝, API Server 보안, etcd 암호화)            │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 각 계층 개요

### Layer 1: 인프라 보안

```
기반이 되는 인프라 자체의 보안:

├── 노드 하드닝
│   ├── 최소 OS 설치 (Bottlerocket 등)
│   ├── SSH 접근 제한
│   └── CIS 벤치마크 적용
│
├── API Server 보안
│   ├── 인증 필수
│   ├── 감사 로깅 활성화
│   └── 익명 접근 차단
│
└── etcd 보안
    ├── 암호화 at rest
    ├── TLS 통신
    └── 접근 제한
```

### Layer 2: 신원 및 접근 관리

```
누가 무엇을 할 수 있는지:

├── RBAC (Role-Based Access Control)
│   └── 최소 권한 원칙
│
├── ServiceAccount
│   └── Pod별 적절한 권한
│
└── IAM 통합 (Hybrid Nodes)
    └── AWS IAM으로 인증/인가
```

### Layer 3: 네트워크 보안

```
Pod 간, 외부 통신 제어:

├── Network Policy
│   └── Pod 간 트래픽 제어
│
├── Service Mesh (선택)
│   └── mTLS, 트래픽 관리
│
└── 방화벽
    └── 클러스터 경계 보호
```

### Layer 4: 워크로드 보안

```
컨테이너와 Pod 수준 보안:

├── Pod Security Standards
│   └── 위험한 설정 차단
│
├── 이미지 보안
│   └── 취약점 스캐닝
│
└── 런타임 보안
    └── 이상 행위 탐지
```

### Layer 5: 데이터 보안

```
민감 데이터 보호:

├── Secrets 관리
│   └── 외부 시크릿 관리자 연동
│
├── 암호화
│   └── 전송 중, 저장 시 암호화
│
└── 백업
    └── 재해 복구 대비
```

## EKS Hybrid Nodes vs EKS Anywhere 보안 비교

| 보안 영역 | EKS Hybrid Nodes | EKS Anywhere |
|----------|------------------|--------------|
| **API Server 보안** | AWS 관리 | 직접 관리 |
| **etcd 암호화** | AWS 관리 | 직접 구성 |
| **인증** | IAM 통합 | OIDC 직접 구성 |
| **감사 로그** | CloudTrail | 직접 구성 |
| **노드 보안** | 직접 관리 | 직접 관리 |
| **네트워크 보안** | 직접 관리 | 직접 관리 |
| **GuardDuty** | ✅ 지원 | ❌ 미지원 |
