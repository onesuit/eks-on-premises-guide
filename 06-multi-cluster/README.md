# Multi-Cluster 운영

> "클러스터 하나도 복잡한데, 왜 여러 개를 운영해야 하나요?"

하이브리드 환경에서는 자연스럽게 여러 클러스터를 운영하게 됩니다. 클라우드와 온프레미스, Dev와 Prod, 지역별 클러스터 등. 이 장에서는 Multi-Cluster 전략을 알아봅니다.

## Multi-Cluster가 필요한 이유

### 단일 클러스터의 한계

```
┌─────────────────────────────────────────────────────────────────┐
│                    단일 클러스터 운영                            │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                   하나의 클러스터                        │  │
│   │                                                          │  │
│   │   Dev ─────┬───── Staging ─────┬───── Production        │  │
│   │            │                   │                         │  │
│   │   문제점:                                                │  │
│   │   ├── 장애 전파 위험 (Dev 실수 → Prod 영향)            │  │
│   │   ├── 리소스 경쟁 (Dev가 리소스 독점)                  │  │
│   │   ├── 업그레이드 어려움 (모든 환경 동시 영향)          │  │
│   │   ├── 보안 경계 불명확                                  │  │
│   │   └── 규모 한계 (노드 5000개, Pod 150000개)            │  │
│   │                                                          │  │
│   └──────────────────────────────────────────────────────────┘ │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Multi-Cluster로 해결

```
┌─────────────────────────────────────────────────────────────────┐
│                    Multi-Cluster 운영                            │
│                                                                 │
│   ┌──────────────┐  ┌──────────────┐  ┌──────────────┐        │
│   │     Dev      │  │   Staging    │  │  Production  │        │
│   │   Cluster    │  │   Cluster    │  │   Cluster    │        │
│   │              │  │              │  │              │        │
│   │  ┌────────┐  │  │  ┌────────┐  │  │  ┌────────┐  │        │
│   │  │ Apps   │  │  │  │ Apps   │  │  │  │ Apps   │  │        │
│   │  └────────┘  │  │  └────────┘  │  │  └────────┘  │        │
│   └──────────────┘  └──────────────┘  └──────────────┘        │
│                                                                 │
│   이점:                                                         │
│   ├── 환경 간 완전 격리                                        │
│   ├── 독립적인 업그레이드                                      │
│   ├── 장애 영향 범위 제한                                      │
│   └── 클러스터별 최적화                                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## Multi-Cluster 패턴

### 패턴 1: 환경별 분리

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   Development        Staging           Production               │
│   ┌──────────┐      ┌──────────┐      ┌──────────┐             │
│   │ EKS      │      │ EKS      │      │ EKS      │             │
│   │ Cluster  │ ───► │ Cluster  │ ───► │ Cluster  │             │
│   │          │      │          │      │ (HA)     │             │
│   │ 1 Node   │      │ 3 Nodes  │      │ 10 Nodes │             │
│   └──────────┘      └──────────┘      └──────────┘             │
│                                                                 │
│   특징:                                                         │
│   • Dev: 비용 최소화, 빠른 반복                                │
│   • Staging: Prod와 유사, 테스트용                             │
│   • Prod: 고가용성, 보안 강화                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 패턴 2: 지역별 분리

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   Seoul Region       Busan Region       Tokyo Region            │
│   ┌──────────┐      ┌──────────┐      ┌──────────┐             │
│   │ EKS      │      │ EKS      │      │ EKS      │             │
│   │ Anywhere │      │ Anywhere │      │ Anywhere │             │
│   │          │      │          │      │          │             │
│   │ 사용자A  │      │ 사용자B  │      │ 사용자C  │             │
│   └──────────┘      └──────────┘      └──────────┘             │
│        │                 │                 │                    │
│        └─────────────────┴─────────────────┘                    │
│                          │                                      │
│                    글로벌 트래픽 관리                           │
│                                                                 │
│   특징:                                                         │
│   • 지역별 낮은 레이턴시                                       │
│   • 데이터 주권 준수                                           │
│   • 리전 장애 격리                                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 패턴 3: 하이브리드 분리

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   AWS Cloud                      On-Premises                    │
│   ┌────────────────────┐        ┌────────────────────┐         │
│   │                    │        │                    │         │

│   │  │ EKS Cluster  │  │        │  │ EKS Hybrid   │  │         │
│   │  │              │  │◄──────►│  │ or Anywhere  │  │         │
│   │  │ • 웹 서비스  │  │        │  │              │  │         │
│   │  │ • 스케일링   │  │        │  │ • 민감 데이터│  │         │
│   │  │ • 버스팅     │  │        │  │ • 레거시     │  │         │
│   │  └──────────────┘  │        │  └──────────────┘  │         │
│   │                    │        │                    │         │
│   └────────────────────┘        └────────────────────┘         │
│                                                                 │
│   특징:                                                         │
│   • 워크로드별 최적 위치                                       │
│   • 클라우드 버스팅                                            │
│   • 데이터 지역성                                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
