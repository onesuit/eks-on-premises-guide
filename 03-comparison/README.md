# EKS Hybrid Nodes vs EKS Anywhere

> "둘 다 온프레미스에서 EKS를 운영하는 거 아닌가요? 뭐가 다른 거예요?"

좋은 질문입니다. 두 솔루션 모두 온프레미스에서 Kubernetes를 운영할 수 있게 해주지만, 접근 방식이 근본적으로 다릅니다.

## 한눈에 보는 비교

```
┌─────────────────────────────────────────────────────────────────────┐
│                    EKS Hybrid Nodes                                  │
│                                                                     │
│   AWS Cloud                          On-Premises                    │
│  ┌──────────────────┐              ┌──────────────────┐            │
│  │  Control Plane   │◄───────────►│   Worker Nodes   │            │
│  │  (AWS 관리)      │   연결      │  (고객 관리)     │            │
│  │                  │              │                  │            │
│  │  • API Server    │              │  • kubelet       │            │
│  │  • etcd          │              │  • Container     │            │
│  │  • Scheduler     │              │  • kube-proxy    │            │
│  └──────────────────┘              └──────────────────┘            │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│                    EKS Anywhere                                      │
│                                                                     │
│                        On-Premises (전체)                           │
│  ┌──────────────────────────────────────────────────────────┐      │
│  │                                                          │      │
│  │  ┌──────────────────┐      ┌──────────────────┐         │      │
│  │  │  Control Plane   │      │   Worker Nodes   │         │      │
│  │  │  (고객 인프라)   │◄────►│  (고객 인프라)   │         │      │
│  │  │                  │      │                  │         │      │
│  │  │  EKS Distro     │      │  EKS Distro      │         │      │
│  │  └──────────────────┘      └──────────────────┘         │      │
│  │                                                          │      │
│  │  (선택) AWS 연결: 콘솔 통합, 지원 등                    │      │
│  └──────────────────────────────────────────────────────────┘      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 핵심 차이점 요약

| 관점 | EKS Hybrid Nodes | EKS Anywhere |
|------|------------------|--------------|
| **Control Plane 위치** | AWS 클라우드 | 온프레미스 |
| **Control Plane 관리** | AWS 완전 관리 | 고객이 직접 관리 |
| **AWS 연결** | 필수 | 선택 (Disconnected 모드 지원) |
| **인터넷 연결** | 필수 | 선택 |
| **출시 시기** | 2024년 12월 | 2021년 9월 |
| **타겟 사용자** | 클라우드 중심 하이브리드 | 온프레미스 중심 |

## 언제 무엇을 선택해야 할까?

### EKS Hybrid Nodes가 적합한 경우

```
✅ AWS 서비스(RDS, S3, Lambda 등)와 긴밀한 통합 필요
✅ 안정적인 인터넷 연결 가능
✅ Control Plane 관리 부담을 줄이고 싶음
✅ 이미 AWS EKS를 사용 중이고 온프레미스로 확장하려는 경우
✅ IAM 기반 인증/인가를 사용하고 싶음
```

### EKS Anywhere가 적합한 경우

```
✅ 인터넷 연결이 불안정하거나 없는 환경 (공장, 선박 등)
✅ 데이터가 반드시 온프레미스에만 있어야 함
✅ 완전한 인프라 통제권이 필요
✅ 규정상 클라우드 연결이 제한됨
✅ VMware vSphere 환경에서 운영
```

## 비유로 이해하기

### EKS Hybrid Nodes = 본사에서 관리하는 지점

```
     AWS (본사)                    온프레미스 (지점)
┌──────────────────┐            ┌──────────────────┐
│   경영진 (두뇌)  │◄──────────►│  직원들 (일꾼)   │
│                  │   실시간    │                  │
│  • 의사결정      │   보고/지시 │  • 실제 업무     │
│  • 정책 수립     │            │  • 고객 응대     │
│  • 모니터링      │            │                  │
└──────────────────┘            └──────────────────┘

장점: 본사가 알아서 관리해줌
단점: 본사와 연결이 끊기면 의사결정 불가
```

### EKS Anywhere = 독립적인 프랜차이즈

```
           온프레미스 (독립 운영)
┌──────────────────────────────────────┐
│                                      │
│  ┌────────────┐    ┌────────────┐   │
│  │  경영진    │    │  직원들    │   │
│  │  (두뇌)    │◄──►│  (일꾼)    │   │
│  └────────────┘    └────────────┘   │
│                                      │
│  모든 것을 직접 관리                 │
│                                      │
└──────────────────────────────────────┘
              │
              │ (선택적) 컨설팅/지원
              ▼
         AWS (프랜차이즈 본부)

장점: 완전한 독립, 연결 끊겨도 운영 가능
단점: 모든 관리 부담이 우리에게
```
