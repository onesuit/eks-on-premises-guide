# 들어가며

> "왜 굳이 온프레미스에서 Kubernetes를 운영해야 할까요?"

이 질문에 답하기 전에, 먼저 현재 IT 인프라가 어떻게 변화하고 있는지 살펴보겠습니다.

## 클라우드 시대의 역설

2010년대 중반, 모든 것을 클라우드로 옮기는 것이 대세였습니다. "클라우드 퍼스트(Cloud First)" 전략이 유행했고, 많은 기업들이 온프레미스 데이터센터를 축소하거나 없애기 시작했습니다.

그런데 재미있는 일이 일어났습니다.

- **2015년**: "모든 것을 클라우드로!"
- **2018년**: "음... 이건 클라우드로 못 옮기겠는데?"
- **2020년**: "하이브리드가 답이다"
- **2024년**: "워크로드에 맞는 곳에서 운영하자"

완전한 클라우드 전환이 어려운 이유가 하나씩 드러나기 시작했습니다.

## 온프레미스가 여전히 필요한 이유

### 1. 규정 준수 (Compliance)

금융, 의료, 공공 기관은 데이터 저장 위치에 대한 엄격한 규정이 있습니다.

> 💡 **참고**
>
> **실제 사례**
>
> 한국의 개인정보보호법, EU의 GDPR, 미국의 HIPAA 등은 특정 데이터가 어디에 저장되어야 하는지 명시합니다. 환자의 의료 기록이 해외 클라우드 리전에 저장되면 법적 문제가 될 수 있습니다.

### 2. 레이턴시 (Latency)

물리적 거리는 무시할 수 없습니다.

```
사용자 → 서울 데이터센터: ~5ms
사용자 → AWS 서울 리전: ~10-20ms
사용자 → AWS 도쿄 리전: ~30-50ms
사용자 → AWS 버지니아 리전: ~150-200ms
```

실시간 거래 시스템, 게임 서버, 산업용 IoT 시스템에서는 이 차이가 치명적일 수 있습니다.

### 3. 데이터 중력 (Data Gravity)

데이터는 무겁습니다. 문자 그대로요.

> ⚠️ **주의**
>
> **데이터 중력이란?**
>
> 데이터가 많이 모인 곳에 애플리케이션과 서비스가 자연스럽게 끌려가는 현상입니다. 페타바이트 규모의 데이터를 클라우드로 옮기는 것은 시간과 비용 면에서 비현실적일 수 있습니다.

예를 들어, 100TB의 데이터를 1Gbps 회선으로 전송하면:

```
100TB ÷ 1Gbps ≈ 9.3일 (24시간 풀가동 기준)
```

여기에 클라우드 데이터 전송 비용까지 더하면...

### 4. 기존 투자 보호

10년 전에 구축한 데이터센터, 5년 전에 도입한 스토리지 시스템. 이런 자산들을 하루아침에 버릴 수는 없습니다. 감가상각이 끝나지 않은 장비들도 있고, 특정 하드웨어에서만 동작하는 레거시 애플리케이션도 있습니다.

### 5. 비용

클라우드가 항상 저렴한 것은 아닙니다.

| 상황 | 더 유리한 옵션 |
|------|---------------|
| 예측 가능하고 안정적인 워크로드 | 온프레미스 |
| 변동이 크고 스파이크가 있는 워크로드 | 클라우드 |
| 초기 투자 여력이 없음 | 클라우드 |
| 장기적으로 운영 (5년+) | 온프레미스 |

## 그래서 하이브리드로

결국 대부분의 기업은 **하이브리드** 환경에서 운영하게 됩니다.

```
┌─────────────────────────────────────────────────────────────┐
│                      기업 IT 환경                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   ┌─────────────┐              ┌─────────────────────┐      │
│   │  퍼블릭     │              │    온프레미스        │      │
│   │  클라우드   │◄────────────►│    데이터센터       │      │
│   │             │   연결       │                     │      │
│   │  • 웹 서비스│              │  • 레거시 시스템    │      │
│   │  • 개발환경 │              │  • 민감 데이터      │      │
│   │  • DR 사이트│              │  • 저지연 서비스    │      │
│   └─────────────┘              └─────────────────────┘      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

문제는 이 두 환경을 **어떻게 일관되게 운영할 것인가**입니다.

## Kubernetes: 일관성의 열쇠

Kubernetes는 이 문제의 해답이 될 수 있습니다. 왜냐하면:

1. **추상화**: 인프라가 어디에 있든 동일한 방식으로 애플리케이션을 배포
2. **이식성**: 클라우드에서 개발하고, 온프레미스에서 운영 가능
3. **표준화**: 팀 전체가 동일한 도구와 워크플로우 사용

다음 페이지에서는 왜 온프레미스에서 Kubernetes를 운영하는 것이 좋은 선택인지 더 자세히 알아보겠습니다.
